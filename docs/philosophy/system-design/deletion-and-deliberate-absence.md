# 削除と意図的な不在（Deletion and Deliberate Absence）

不要な検査、重複した補助関数、または過剰なガードレールの削除は、品質低下ではなく、システムの信頼性と保証（Assurance）を向上させる設計行為である。

権威が重複した機構や偶発的な実装構造を守る検査を排除することにより、「単一の信頼できる定義」「それを保護する単一のメカニズム」「結果から得られる明確な証拠」という、責任の最短連鎖を確立する。

## 意図的な不在の記録

意図的に実装を見送った機構（意図的な不在）は、背景を共有しない将来の保守者によって「考慮漏れ」と誤認されるリスクがある。十分な文脈が記録されていない場合、過去に意図して排除された冗長なヘルパーや不要な抽象化が再導入される要因となる。

設計文書および ADR は、以下の事項を永続化しなければならない。

* 根底にある事実を所有する単一コンポーネント
* 本来の保証を提供する単一メカニズム
* **意図的に存在させない並行機構の特定**
* **不在によって保護される責務境界およびアーキテクチャ上の根拠**

本記録は、一時的な実装差分の説明ではなく、長期にわたり維持すべき恒久的な責務境界の根拠として記述されなければならない。

## 削除の規律

既存のガードレールや検査を削除する際は、それが担保していた具体的リスクを特定し、当該リスクが代替メカニズムによって適切に観測または抑止されていることを検証する。

削除完了後のリポジトリは、競合する複数の権威が排除され、問題発生時の調査境界が客観的に特定可能な状態でなければならない。
