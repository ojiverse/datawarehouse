# 正しさを判定する評価基準を最初に築く（Optimize Function First）

システム開発において中核となる資産は、**変更の妥当性を即座に検知可能な高速の検証ループ**である。

検証ループを機能させるためには、変更結果を客観的に評価する**判定基準（オラクルや判定器）**が不可欠である。正当性の判定基準を欠いた状態での変更は、客観的検証を欠いた試行錯誤にとどまり、意図しない退行（リグレッション）を検知できない。

## 実装に先立つ客観的判定器の確立

新規機能の開発や既存改修において最優先すべき作業は、実装コードの記述ではなく、**期待される結果が得られたことを機械的に証明する判定器を先行して構築すること**である。

客観的判定器が存在することで、変更の妥当性を主観に頼ることなく迅速に判定可能となる。

課題の性質に応じた判定器の具体例を以下に示す。

* **データ処理および正規化**: 入力ペイロードと期待される抽出結果を定義した検証データセットの事前整備。
* **状態遷移および不変条件の保護**: 不正な遷移や不正データの混入を即座に拒絶するプロパティベースの検証機構の導入。
* **外部通信連携**: 通信挙動をシミュレートし、通信ログおよび永続化結果を検証可能な再現環境の確立。
* **アーキテクチャ変更**: 静的型定義を厳密化し、設計規約違反をコンパイル時に機械的に排除するモデルの先行定義。

## 自動化・機械実装における評価基準の先行

生成 AI や自動化エージェントを活用した開発において、評価基準の先行は成否を決定づける中核要素となる。

判定基準が存在しない状態での機械生成は、人間による行単位の解読と検証コストを増大させる。一方、客観的判定器が先行定義されていれば、機械は合格を満たすまで自律的に修正を反復可能となり、人間は判定結果という客観的証拠を通じて成果物を検証できる。

**評価基準を先行して確立し、その後に最小限の実装を適用する**という順序の徹底により、手戻りを最小化し、論理的確信を持って開発を推進する。
