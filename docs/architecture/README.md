# アーキテクチャ設計

本ディレクトリでは、[ドメイン設計](../domain/README.md) において定義された意味論および保証要件を、特定プラットフォームの能力と制約の下で具現化するためのアーキテクチャ設計を定義する。

## アーキテクチャ設計の役割と位置づけ

* **ドメイン設計**: プラットフォーム非依存の概念モデル、意味論、およびデータ不変条件の定義。
* **アーキテクチャ設計**: ドメイン要求を充足するためのアプリケーションコンポーネント分割、相互協調、およびプラットフォーム提供機能（ランタイム、ストレージ、キュー等）の組み合わせ設計。
* **インフラストラクチャ設計**: 具体的なリソース名、Cloudflare Workers バインディング、環境定義、デプロイ、IaC、コスト管理の定義。

プラットフォーム制約（メモリ上限、タイムアウト、レート制限等）によるドメイン要件のスコープ調整は許容される。ただし、その場合であっても選択理由およびドメイン要件との対応関係を明確に記録しなければならない。

## 採用プラットフォームの構成

本システムの主要実行基盤として **Cloudflare** を採用する。
Cloudflare 上でのコンポーネント協調およびパイプライン構成は、以下のエントリポイント配下で定義される。

* [cloudflare/](cloudflare/README.md): Cloudflare を基盤としたアプリケーションアーキテクチャ

※ 将来的に別プラットフォーム（AWS、GCP 等）への移行またはハイブリッド展開を行う場合は、本ディレクトリ配下に並列でディレクトリ（例: `aws/`）を追加し、同一ドメイン要件に対する実装方式の対比を可能とする。
