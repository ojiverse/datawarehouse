# アーキテクチャ設計

本ディレクトリでは、[ドメイン設計](../domain/README.md) で定義された意味論や保証要件を、特定のプラットフォームが持つ能力と制約の下でどのように成立させるかを設計します。

## アーキテクチャ設計の役割と位置づけ

* **ドメイン設計**: プラットフォームに依存しない、Discord DWH としての概念モデルやデータ不変条件を定義する。
* **アーキテクチャ設計**: ドメインの要求を満たすために、アプリケーションコンポーネントをどう分割・協調させ、プラットフォームの提供機能（ランタイム、ストレージ、キュー等）をどう組み合わせるかを定義する。
* **インフラストラクチャ設計**: 具体的なリソース名、Cloudflare Workers バインディング、環境定義、デプロイ、IaC、コスト予算などを定義する。

特定プラットフォームの制約（例: メモリ制限、タイムアウト、レート制限）がドメイン要件のスコープに影響を与えることは現実的に許容されます。ただし、その場合も「なぜそのアーキテクチャを選択したのか」というドメイン要件との対応関係を明確に記録します。

## 採用プラットフォームの構成

現在、本プロジェクトの主要実行基盤として **Cloudflare** を採用しています。
Cloudflare 上での具体的なコンポーネント連携やパイプライン構成は、以下のエントリポイントから展開されます。

* [cloudflare/](cloudflare/README.md): Cloudflare を基盤としたアプリケーションアーキテクチャ

※ 将来的に別プラットフォーム（例: AWS、GCP、または自前クラスタ）への移行やハイブリッド構成を検討する場合は、本ディレクトリ配下に並列でディレクトリ（例: `aws/`）を追加し、同一のドメイン要件を異なる基盤上で実現する設計を対比できるようにします。
